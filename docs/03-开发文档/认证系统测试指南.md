## 测试场景

### 场景 1: 用户注册

**步骤**:
1. 打开浏览器访问 `http://localhost:5173`
2. 点击右上角的"注册"按钮
3. 填写注册表单：
   - 用户名: `testuser`
   - 邮箱: `test@example.com`
   - 密码: `password123`
   - 确认密码: `password123`
4. 点击"注册"按钮

**预期结果**:
- 注册成功后跳转到登录页
- 浏览器控制台显示 `✅ 注册成功`
- 后端日志显示用户已创建

**可能的错误**:
- 用户名已存在：显示错误提示
- 邮箱格式不正确：显示错误提示
- 密码不匹配：显示错误提示

### 场景 2: 用户登录

**步骤**:
1. 在登录页填写表单：
   - 用户名: `testuser`
   - 密码: `password123`
2. 点击"登录"按钮

**预期结果**:
- 登录成功后跳转到首页
- 浏览器控制台显示 `✅ 登录成功`
- 导航栏显示用户名 `testuser` 和"登出"按钮
- 本地存储中保存了 `token` 和 `user` 信息

**可能的错误**:
- 用户名或密码错误：显示错误提示
- 用户不存在：显示错误提示

### 场景 3: 访问受保护的路由

**步骤**:
1. 登出（点击导航栏的"登出"按钮）
2. 尝试访问 `http://localhost:5173/chat`

**预期结果**:
- 自动重定向到登录页
- 浏览器控制台显示 `✅ 登出成功`

### 场景 4: 本地存储恢复

**步骤**:
1. 登录
2. 刷新页面（F5）
3. 检查导航栏

**预期结果**:
- 页面刷新后仍然保持登录状态
- 导航栏显示用户名和"登出"按钮
- 可以直接访问受保护的路由

### 场景 5: 访问 AI 对话功能

**步骤**:
1. 登录
2. 点击首页的"AI 对话"卡片或导航栏的"对话"链接
3. 发送一条消息

**预期结果**:
- 成功进入对话页面
- 可以正常发送消息和接收回复
- 对话历史正确保存

### 场景 6: 登出功能

**步骤**:
1. 登录
2. 点击导航栏的"登出"按钮

**预期结果**:
- 登出成功
- 跳转到登录页
- 本地存储中的 `token` 和 `user` 被清除
- 导航栏消失

## 常见问题排查

### 问题 1: 注册时显示"用户已存在"

**原因**: 用户名已经被注册过

**解决方案**: 使用不同的用户名重新注册

### 问题 2: 登录时显示"用户名或密码错误"

**原因**: 
- 用户名拼写错误
- 密码错误
- 用户不存在

**解决方案**: 检查用户名和密码，或重新注册

### 问题 3: 登录后导航栏没有显示用户信息

**原因**:
- 认证状态没有正确初始化
- 本地存储中的数据损坏

**解决方案**:
1. 打开浏览器开发者工具
2. 清除本地存储：`localStorage.clear()`
3. 刷新页面
4. 重新登录

### 问题 4: 访问受保护的路由时没有重定向到登录页

**原因**: 路由守卫没有正确配置

**解决方案**:
1. 检查 `frontend/src/router/index.js` 中的路由配置
2. 确保 `requiresAuth: true` 被正确设置
3. 检查路由守卫逻辑

### 问题 5: 后端返回 401 错误

**原因**: Token 无效或过期

**解决方案**:
1. 清除本地存储
2. 重新登录
3. 或调用 `refreshToken()` 刷新 Token

## 安全测试

### 测试 SQL 注入

```bash
# 尝试 SQL 注入（应该被拒绝）
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin\" OR \"1\"=\"1","password":"anything"}'
```

### 测试 XSS 攻击

```bash
# 尝试在用户名中注入脚本（应该被转义）
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"<script>alert(1)</script>","email":"test@example.com","password":"password123","confirmPassword":"password123"}'
```

### 测试无效 Token

```bash
# 使用无效 Token 访问受保护的端点
curl -X GET http://localhost:3000/api/auth/me \
  -H "Authorization: Bearer invalid_token"
```
